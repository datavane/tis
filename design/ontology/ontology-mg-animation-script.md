## 第四幕：五虎上将——本体实体全阵容（4:50 – 7:30，160 秒）

### 【画面】

**ObjectType（4:50 – 5:25）**：蓝色立方体磁吸聚合，表面浮现 `sales_order` 表结构。Doris/MySQL/Oracle 图标排成一排，表结构被"吸"出落入本体域，主键外键自动描金边。立方体翻转，正面"销售订单"，背面物理表名。花字："ObjectType：业务实体一键导出。"

**Property（5:25 – 6:00）**：字段方块雨弹出，被角色印章染色：`order_id` 盖 Identifier（白）、`city` 盖 Dimension（蓝）、`order_date` 盖 TimeDimension（绿）、`order_amount` 盖 Measure（橙）。Measure 方块被放大镜聚焦，聚合函数轮盘（SUM/AVG/COUNT/COUNT DISTINCT/MIN/MAX/APPROX_COUNT_DISTINCT）停在 SUM，`order_amount` 变金色。花字："语义角色 + 聚合规则，大模型不再猜口径。"

**Linker（6:00 – 6:30）**：三座大厦（订单/客户/部门）架起发光桥梁，刻着外键名。光点从订单出发，两跳到达部门，路径高亮。一条乱连的红色野线刚冒出，被白名单闸门截断。花字："Linker：JOIN 白名单，杜绝笛卡尔积。"

**Glossary（6:30 – 7:00）**：橙色词典翻开，动态书写词条"销售额"，同义词 GMV/成交金额/revenue，指向 `SUM(order_amount)`。测速动画：输入"GMV"秒命中，秒表 <10ms；输入"客单价"直接吐出 SQL 公式。花字："Glossary：业务黑话的官方翻译官。"

**Constraint（7:00 – 7:30）**：四面盾牌旋转：枚举盾、范围盾、正则盾、时间盾。一条 `WHERE age = 9999` 飞过来被弹飞。五大实体聚合成本体徽章，徽章射光照亮 Neo4j 图球体。花字："Constraint：给字段立规矩。"

### 【旁白】

ObjectType，对象类型，一张业务表就是一个对象，从数据源一键导出，主键外键自动识别。Property，属性，每个字段盖上语义角色印章：标识列、分组维度、时间维度、可聚合度量。度量还能绑定十多种聚合函数——销售额用 SUM，客单数用 COUNT DISTINCT，大模型从此不用猜口径。Linker，关系类型，把外键刻成桥梁，更是一份 JOIN 白名单：没在名单里的连接，一律拦截。Glossary，业务术语词典，GMV、成交金额、revenue 映射到同一个指标定义，四成高频查询 O(1) 秒级命中。Constraint，约束体系，枚举、范围、正则、时间窗口，让筛选条件永远不出格。五位一体，这就是 TIS Ontology。

- "ObjectType · Property · Linker · Glossary · Constraint"
- "40% 高频查询 <10ms 命中"

### 【旁白】

## 第六幕：一次问数的完整旅程（9:40 – 12:25，165 秒）

### 【画面】

左侧聊天框，用户键入："2025 年各城市的销售总额排名前 10"。右侧六节点进度环：**检索 → 拼装 → 生成 → 校验 → 执行 → 返回**。

节点 1、2 点亮：子图胶囊飞入 Prompt 组装车间，系统提示词（Doris 方言规则）与业务上下文拼合。节点 3 点亮：大模型大脑闪烁，吐出 SQL 卡片，关键字高亮：

```sql
SELECT c.city, SUM(o.order_amount) AS total_sales
FROM sales_order o JOIN customer c ON o.customer_id = c.customer_id
WHERE DATE_TRUNC(o.order_date, 'year') = '2025-01-01'
GROUP BY c.city ORDER BY total_sales DESC LIMIT 10
```

节点 4 点亮，**三道安检门**逐一下落：1）关键字白名单门，只放行 SELECT 类，DROP/DELETE 被红门拍碎，字幕"**安全底线，绝不重试**"；2）AST 校验门，语法树拆解表名/列名/JOIN，逐一盖绿勾；3）EXPLAIN 动态校验门，Doris 预演通过，反例小窗 `DATEDIFF` 被拦截提示应为 `date_diff`。盾牌徽章：**"危险 SQL 拦截率 100% · 低效查询拦截率 98%"**。小注：校验失败自动回喂大模型修正，最多重试 2 次。

节点 5 点亮：SQL 飞入 Doris，数据喷涌，十座城市柱条竞速升起。节点 6 点亮：交付界面——结果表格 + SQL + 执行摘要（**总耗时 3.2 秒**）。用户点开 Trace，六步完整日志透明展开。花字：**"不是黑盒，是玻璃盒。"**

### 【旁白】

用户只输一句话：2025 年各城市的销售总额排名前 10。第一步 GraphRAG 检索本体；第二步 Prompt 组装器拼好 Doris 方言规则和业务上下文；第三步大模型生成 SQL。重头戏是第四步——三道安检门。关键字白名单只放行 SELECT，DROP/DELETE 直接拍碎，绝不重试，这是安全底线。AST 校验把 SQL 拆成语法树，每个表、每个字段、每个 JOIN 都核对白名单。EXPLAIN 动态校验让 Doris 先预演，方言错误、类型错误、聚合错误统统现形。三道门下来，危险 SQL 拦截率百分之百。第五步 Doris 执行，十城销售榜秒级出炉。第六步结果返回，附赠完整 Trace 日志——检索了什么、提示词是什么、SQL 怎么来的，全程透明。对用户，只有三秒二。对系统，六次精密协作。
